= Mantén las instancias de VM del agente de NetApp Console
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Mantén las VM del agente de NetApp Console aplicando actualizaciones de seguridad del sistema operativo a los agentes instalados manualmente, respondiendo a las alertas de CPU, RAM y espacio en disco, y cambiando el tamaño de las VM o deteniéndolas e iniciándolas de nuevo cuando sea necesario.

Cuando instalas manualmente un agente de Console, mantener el sistema operativo en el host del agente es tu responsabilidad (del cliente). Por ejemplo, tú (el cliente) deberías aplicar actualizaciones de seguridad al sistema operativo en el host del agente siguiendo los procedimientos estándar de tu empresa para la distribución del sistema operativo.

Si una VM de agente se queda sin recursos suficientes o presenta problemas de rendimiento, debes tomar las medidas adecuadas para ampliar los recursos de la VM.


NOTE: Si has instalado el agente en vCenter, usa la herramienta de mantenimiento de Console para cambiar el tamaño de la instancia de VM. link:task-agent-vm-config.html["Aprende a mantener una VM de agente en vCenter"^].



[[apply-operating-system-updates-to-the-manually-installed-agent-hosts]]
== Aplica las actualizaciones del sistema operativo a los hosts del agente instalados manualmente

Aplicar parches de seguridad del sistema operativo sin detener los servicios del host del agente.

Para mantener la compatibilidad con las configuraciones admitidas, debes evitar que Docker o Podman se actualicen durante la aplicación rutinaria de parches del sistema operativo. Puedes hacerlo excluyendo temporalmente Docker o Podman durante las actualizaciones o configurando permanentemente el gestor de paquetes para que omita las actualizaciones de Docker o Podman.

Los siguientes son ejemplos de cómo excluir actualizaciones de Docker o Podman para diferentes distribuciones de Linux. Consulta la documentación de tu distribución de Linux para obtener las instrucciones más actualizadas sobre cómo excluir paquetes de las actualizaciones.

.Ejemplo de Podman
[source, bash]
----
sudo yum update --exclude=podman
sudo yum upgrade
----
.Ejemplo de Docker
[source, bash]
----
sudo apt-mark hold docker-ce docker-ce-cli containerd.io
sudo apt update
sudo apt upgrade
----


[[resizing-the-vm-or-instance-type]]
== Cambiar el tamaño de la VM o el tipo de instancia

Si crea un agente de consola desde la consola, implementará una instancia de VM en su proveedor de nube con una configuración predeterminada.  Después de crear el agente, no cambie a una instancia de VM más pequeña con menos CPU o RAM.

Si recibes notificaciones indicando que tu máquina virtual (VM) del agente no cuenta con los recursos suficientes, plantéate pasar a una instancia de VM más potente, con más CPU o RAM, para garantizar un rendimiento óptimo.


NOTE: Si instalaste el agente en VCenter, usa la herramienta de mantenimiento de Console para cambiar el tamaño de la instancia de VM. link:task-agent-vm-config.html["Aprende a cambiar el tamaño de la máquina virtual del agente en VCenter"^].

link:reference-agent-default-config.html["Obtenga información sobre la configuración predeterminada del agente"] .

Si necesitas aumentar la CPU o la RAM de tu VM del agente, sigue las instrucciones proporcionadas por tu proveedor de nube o por tu plataforma de virtualización on-premises para cambiar el tamaño de la instancia de VM. NetApp recomienda duplicar la asignación actual de CPU y RAM para garantizar un rendimiento óptimo. La siguiente tabla muestra los niveles de dimensionamiento recomendados, donde cada nivel duplica la CPU y la RAM del nivel anterior.

[cols="1,1,1"]
|===
| Nivel | CPU (núcleos o vCPUs) | RAM 


| Mínimo | 8 | 32 GB 


| Medio | 16 | 64 GB 


| Grande | 32 | 128 GB 
|===

== Monitorear al agente

La consola le notifica cuando la máquina virtual del agente no está en buen estado, incluidos problemas de espacio en disco, RAM y CPU.  Supervise estas notificaciones en el Centro de notificaciones dentro de la Consola o configure notificaciones por correo electrónico.  Los aumentos ocasionales en el espacio en disco, la memoria o el uso de la CPU son normales, pero si sucede con frecuencia, debe tomar medidas para resolverlo.

Por ejemplo, la consola le notifica cuando un recurso del agente (CPU, RAM o espacio en disco) excede el 90 % de su capacidad total durante 30 minutos consecutivos.  Posteriormente, si el uso de recursos cae por debajo de ese umbral, la notificación se muestra como resuelta (verde) en el Centro de notificaciones.


NOTE: Trabaja con NetApp Support si tienes preguntas sobre cómo modificar tu VM agente.

== Conectarse a la máquina virtual Linux

Si necesita conectarse a la máquina virtual Linux en la que se ejecuta el agente, utilice las opciones de conectividad de su proveedor de nube.

AWS:: Cuando cree la instancia del agente en AWS, proporcione una clave de acceso y una clave secreta de AWS.  Puede utilizar este par de claves para conectarse mediante SSH a la instancia.  Utilice el nombre de usuario 'ubuntu' para la instancia EC2 Linux.  Para los agentes creados antes de mayo de 2023, utilice el nombre de usuario "ec2-user".
+
--
https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/AccessingInstances.html["Documentación de AWS: Conéctese a su instancia de Linux"^]

--
Azur:: Cuando crea la máquina virtual del agente en Azure, especifica un nombre de usuario y elige autenticarse con una contraseña o una clave pública SSH.  Utilice el método de autenticación que eligió para conectarse a la máquina virtual.
+
--
https://docs.microsoft.com/en-us/azure/virtual-machines/linux/mac-create-ssh-keys#ssh-into-your-vm["Documentación de Azure: SSH en su máquina virtual"^]

--
Google Cloud:: No puedes especificar un método de autenticación cuando creas un agente en Google Cloud.  Sin embargo, puedes conectarte a la instancia de VM Linux mediante Google Cloud Console o Google Cloud CLI (gcloud).
+
--
https://cloud.google.com/compute/docs/instances/connecting-to-instance["Google Cloud Docs: Conectarse a máquinas virtuales Linux"^]
