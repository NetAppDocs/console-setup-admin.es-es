[[apply-operating-system-updates-to-agent-hosts]]
== Aplica las actualizaciones del sistema operativo a los hosts de los agentes

Aplica las actualizaciones de seguridad al sistema operativo y a los paquetes asociados en el host del agente para que el host se mantenga seguro.

Esto es tu responsabilidad como cliente. El software del agente de NetApp Console puede actualizarse automáticamente, pero no actualiza el sistema operativo ni los paquetes asociados.


NOTE: Si implementaste el agente de NetApp Console en vCenter mediante un archivo OVA, el sistema operativo forma parte de la imagen del agente. link:task-upgrade-agent.html#upgrade-a-vcenter-deployed-console-agent-using-an-iso["Actualiza el agente mediante una imagen ISO"^] para actualizar el sistema operativo.

Sigue los procedimientos estándar de tu empresa para la distribución de tu sistema operativo. No necesitas detener los servicios del host del agente cuando apliques parches de seguridad del sistema operativo.

En los agentes que no hayas desplegado desde un OVA, evita que Docker o Podman se actualicen durante el parcheo rutinario del sistema operativo para mantener la compatibilidad con las configuraciones compatibles. Puedes hacerlo excluyendo temporalmente Docker o Podman durante las actualizaciones o configurando de forma permanente el gestor de paquetes para que omita las actualizaciones de Docker o Podman.

Los siguientes son ejemplos de cómo excluir actualizaciones de Docker o Podman para diferentes distribuciones de Linux. Consulta la documentación de tu distribución de Linux para obtener las instrucciones más actualizadas sobre cómo excluir paquetes de las actualizaciones.

.Ejemplo de Podman
[source, bash]
----
sudo yum update --exclude=podman
sudo yum upgrade
----
.Ejemplo de Docker
[source, bash]
----
sudo apt-mark hold docker-ce docker-ce-cli containerd.io
sudo apt update
sudo apt upgrade
----


[[resize-the-vm-or-instance-type]]
== Cambiar el tamaño de la VM o el tipo de instancia de VM

Aumenta la CPU o la RAM de una instancia de VM del agente con recursos insuficientes para que el agente siga funcionando correctamente.

Si creas un agente de NetApp Console desde NetApp Console, se implementa una instancia de VM en tu proveedor de servicios en la nube con una configuración predeterminada. link:reference-agent-default-config.html["Más información sobre la configuración predeterminada del agente"]. Después de crear el agente, no cambies a una instancia de VM más pequeña con menos CPU o RAM.

Si recibes notificaciones indicando que tu máquina virtual (VM) de agente no cuenta con los recursos suficientes, plantéate pasar a una instancia de VM más potente, con mayor capacidad de CPU o RAM.


NOTE: Si has instalado el agente en vCenter, usa la herramienta de mantenimiento de Console para cambiar el tamaño de la instancia de VM. link:task-agent-vm-config.html["Aprende a cambiar el tamaño de la máquina virtual del agente en vCenter"^].

Si necesitas aumentar la CPU o la RAM de tu VM del agente, sigue las instrucciones proporcionadas por tu proveedor de nube o por tu plataforma de virtualización on-premises para cambiar el tamaño de la instancia de VM. NetApp recomienda duplicar la asignación actual de CPU y RAM para garantizar un rendimiento óptimo. La siguiente tabla muestra los niveles de dimensionamiento recomendados, donde cada nivel duplica la CPU y la RAM del nivel anterior.

[cols="1,1,1"]
|===
| Nivel | CPU (núcleos o vCPUs) | RAM 


| Mínimo | 8 | 32 GB 


| Medio | 16 | 64 GB 


| Grande | 32 | 128 GB 
|===

== Monitorear al agente

Mantente al tanto de los problemas relacionados con el espacio en disco, la RAM y la CPU de tu VM de agente para poder resolverlos.

La consola le notifica cuando la máquina virtual del agente no está en buen estado, incluidos problemas de espacio en disco, RAM y CPU.  Supervise estas notificaciones en el Centro de notificaciones dentro de la Consola o configure notificaciones por correo electrónico.  Los aumentos ocasionales en el espacio en disco, la memoria o el uso de la CPU son normales, pero si sucede con frecuencia, debe tomar medidas para resolverlo.

Por ejemplo, la consola le notifica cuando un recurso del agente (CPU, RAM o espacio en disco) excede el 90 % de su capacidad total durante 30 minutos consecutivos.  Posteriormente, si el uso de recursos cae por debajo de ese umbral, la notificación se muestra como resuelta (verde) en el Centro de notificaciones.


NOTE: Trabaja con NetApp Support si tienes preguntas sobre cómo modificar tu VM agente.

[[stop-and-start-the-agent-vm]]
== Detén e inicia la VM del agente

Reduce al mínimo el tiempo de inactividad al detener y reiniciar la VM del agente, ya que los servicios de gestión y de datos dependen de que el agente permanezca operativo.

Si es necesario, detenga e inicie la máquina virtual del agente mediante la consola de su proveedor de nube o los procedimientos locales estándar.

link:concept-agents.html#agents-must-be-operational-at-all-times["Tenga en cuenta que el agente de la consola debe estar operativo en todo momento."] .



[[connect-to-the-linux-vm]]
[[connect-linux-host]]
== Conectarse a la máquina virtual Linux

Comprueba el estado del agente de NetApp Console desde su VM Linux para asegurarte de que está en funcionamiento.

Si necesita conectarse a la máquina virtual Linux en la que se ejecuta el agente, utilice las opciones de conectividad de su proveedor de nube.

AWS:: Cuando cree la instancia del agente en AWS, proporcione una clave de acceso y una clave secreta de AWS.  Puede utilizar este par de claves para conectarse mediante SSH a la instancia.  Utilice el nombre de usuario 'ubuntu' para la instancia EC2 Linux.  Para los agentes creados antes de mayo de 2023, utilice el nombre de usuario "ec2-user".
+
--
https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/AccessingInstances.html["Documentación de AWS: Conéctese a su instancia de Linux"^]

--
Azur:: Cuando crea la máquina virtual del agente en Azure, especifica un nombre de usuario y elige autenticarse con una contraseña o una clave pública SSH.  Utilice el método de autenticación que eligió para conectarse a la máquina virtual.
+
--
https://docs.microsoft.com/en-us/azure/virtual-machines/linux/mac-create-ssh-keys#ssh-into-your-vm["Documentación de Azure: SSH en su máquina virtual"^]

--
Google Cloud:: No puedes especificar un método de autenticación cuando creas un agente en Google Cloud.  Sin embargo, puedes conectarte a la instancia de VM Linux mediante Google Cloud Console o Google Cloud CLI (gcloud).
+
--
https://cloud.google.com/compute/docs/instances/connecting-to-instance["Google Cloud Docs: Conectarse a máquinas virtuales Linux"^]
