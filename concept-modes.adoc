= Obtenga más información sobre los modos de implementación de la NetApp Console
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Puedes usar NetApp Console a través de la aplicación SaaS o instalarla tú mismo en tu propio entorno (cloud o en las instalaciones).

NetApp se refiere a estos casos de uso como _modos de despliegue_. Cada modo ofrece conectividad, funciones y servicios diferentes para tus necesidades empresariales y de seguridad.

Modo estándar (SaaS):: La aplicación SaaS (software-as-a-service) de NetApp Console permite acceder a todos los servicios de datos de NetApp, actualizaciones automáticas y opciones de autenticación flexibles como la federación de identidades y los inicios de sesión en NetApp Support Site. Este modo admite suscripciones de marketplace y licencias BYOL. Este modo es ideal para la mayoría de los usuarios y organizaciones, especialmente para quienes quieren la mayor cantidad de funciones y servicios disponibles con NetApp Console.
Modo restringido (instalado en tu propia nube pública):: El modo restringido es para organizaciones que necesitan seguridad mejorada y conectividad limitada, como gobiernos y empresas reguladas. Tú instalas la NetApp Console en tu propia nube pública (en una región gubernamental, soberana o comercial), y tiene conectividad saliente limitada a los endpoints de la API de la NetApp Console (alojados en la aplicación SaaS). El modo restringido proporciona acceso a servicios clave de datos, incluyendo Cloud Volumes ONTAP, Azure NetApp Files, NetApp Backup and Recovery (en regiones gubernamentales y comerciales) y clasificación de datos, junto con actualizaciones automáticas de software y federación de identidades.
Modo privado (instalado en tus instalaciones o en la nube):: El modo privado es para organizaciones con necesidades de seguridad estrictas, como las que están en AWS Secret Cloud, AWS Top Secret Cloud, Azure IL6 o entornos air-gapped. No se conecta a la aplicación SaaS NetApp Console ni a las APIs basadas en cloud de NetApp, dándote control total y bloqueando la comunicación externa. Los servicios de datos compatibles incluyen NetApp Backup and Recovery, NetApp Data Classification, NetApp Replication y Cloud Volumes ONTAP. Todo el almacenamiento y la autenticación permanecen locales, manteniendo los datos dentro de tu entorno. Usa este modo para contratistas de defensa, instituciones financieras con reglas estrictas de residencia de datos y agencias gubernamentales con sistemas clasificados.


Cuando se instala en tus instalaciones, solo se admiten los sistemas de almacenamiento ONTAP.


NOTE: NetApp Console limita el flujo de datos en modo restringido y privado, pero tienes que asegurarte de que tu entorno cumple con tus regulaciones.

Cada modo de implementación difiere en conectividad de salida, ubicación, instalación, autenticación, servicios de datos y métodos de cobro.

|===

=== Cómo funciona NetApp Console en modo estándar

La consola funciona de la siguiente manera en modo estándar:

Comunicación saliente:: Se requiere conectividad de un agente a la aplicación Console SaaS, a los recursos disponibles públicamente de tu proveedor de cloud y a otros componentes esenciales para las operaciones diarias.
+
--
* link:task-install-agent-aws-console.html#networking-aws-agent["Puntos finales con los que un agente se pone en contacto en AWS"]
* link:task-install-agent-azure-console.html#networking-azure-agent["Puntos de conexión con los que contacta un agente en Azure"]
* link:task-install-agent-google-console-gcloud.html#networking-gcp-agent["Puntos finales con los que un agente se comunica en Google Cloud"]


--
Ubicación admitida para un agente de NetApp Console:: En modo estándar, puedes instalar un agente de Console en la nube o en tus instalaciones.



NOTE: Instalar un agente en la nube genera cargos por uso de la nube.

Actualizaciones del agente de consola:: NetApp actualiza automáticamente el software del agente cada mes.
Acceso a la interfaz de usuario:: Accedes a la interfaz de usuario desde la aplicación Console SaaS, que está disponible a través de internet pública.
Punto final de API:: Las llamadas API se realizan al siguiente punto final: https://api.bluexp.netapp.com
Autenticación:: NetApp Console proporciona autenticación con auth0 o inicios de sesión de NetApp Support Site (NSS). La federación de identidades está disponible.

== NetApp Console en modo restringido (instalada en tu propia nube pública)

Instalas un agente de la Console en la nube (en una región gubernamental, soberana o comercial), y tiene conectividad de salida limitada a los endpoints de la API de la NetApp Console (alojados en la aplicación SaaS).

Los usuarios acceden a la interfaz de usuario local proporcionada por el agente de la NetApp Console, no a la aplicación SaaS.

Dependiendo de los servicios de datos y las funciones que planees usar, un administrador de la organización de la NetApp Console crea agentes adicionales de la NetApp Console para gestionar los datos dentro de tu entorno de cloud híbrida.

=== Cómo funciona NetApp Console en modo restringido

La consola funciona de la siguiente manera en modo restringido:

Comunicación saliente:: Un agente necesita conectividad saliente con las API basadas en cloud de NetApp para soporte de servicios de datos, actualizaciones de software, autenticación y transmisión de metadatos.
+
--
NetApp no inicia la comunicación con un agente. El agente inicia toda la comunicación y puede extraer o enviar datos desde o hacia las NetApp APIs y servicios según sea necesario.

También se requiere una conexión a los recursos del proveedor de la nube desde dentro de la región.

--
Ubicación compatible con un agente:: En modo restringido, instalas agentes en la nube: en una región gubernamental, soberana o comercial.

Punto final de API:: Se hacen llamadas a la API a una máquina virtual agente.
Autenticación:: La autenticación se proporciona a través del servicio en la nube de NetApp Console usando auth0. La federación de identidades también está disponible.




=== Cómo empezar a utilizar el modo restringido

Necesitas activar el modo restringido cuando crees tu cuenta de NetApp Console. Si no tienes una organización, se te pedirá que crees una y que actives el modo restringido cuando inicies sesión por primera vez en tu agente de Console instalado.

Ten en cuenta que la configuración del modo restringido se fija después de crear la organización. No puedes activar ni desactivar el modo restringido después. link:task-quick-start-restricted-mode.html["Aprenda cómo comenzar a utilizar el modo restringido"].

=== Cómo funciona NetApp Console en modo privado

NetApp Console funciona de la siguiente manera en modo privado:

Comunicación saliente:: No se requiere conectividad saliente a la aplicación Console SaaS (donde residen los puntos finales de API adicionales). Todos los paquetes, dependencias y componentes esenciales se empaquetan con el agente de Console y se sirven desde la máquina local. La conectividad a los recursos disponibles públicamente de tu proveedor de cloud solo es necesaria si estás implementando Cloud Volumes ONTAP.
Ubicación admitida para el agente de la NetApp Console:: En modo privado, el agente de la Console es compatible en la nube o en las instalaciones.
Actualizaciones del agente de consola:: Debes actualizar manualmente el software del agente de la Console. NetApp publica el software del agente de la Console en el NetApp Support Site a intervalos indefinidos.
Acceso a la interfaz de usuario:: Los usuarios acceden a la NetApp Console desde el agente de la NetApp Console que está desplegado en tu región de cloud o en las instalaciones.
Punto final de API:: Se hacen llamadas a la API a la máquina virtual del agente de la NetApp Console.
Autenticación:: La autenticación se proporciona a través de la gestión local de usuarios y el acceso. La autenticación no se proporciona a través del servicio cloud de NetApp Console.
