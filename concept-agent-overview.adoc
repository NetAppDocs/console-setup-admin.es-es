Habilitas las capacidades de NetApp Console desplegando agentes de Console, componentes de software ligeros que proporcionan una conexión segura entre tus sistemas de almacenamiento en las instalaciones y en cloud y NetApp Console, permitiendo la orquestación avanzada de almacenamiento y los servicios de datos.



== Qué hace un agente de Console

Un agente de la Consola tiende un puente entre tus sistemas de almacenamiento y la NetApp Console. Conecta de forma segura tu infraestructura a las APIs de NetApp y a la Console, permitiéndote:

* Descubre y supervisa los sistemas de almacenamiento en AWS, Azure, Google Cloud y entornos locales desde la NetApp Console.
* Orquesta las tareas de aprovisionamiento de almacenamiento y configuración en los sistemas de almacenamiento desde la NetApp Console.
* Habilita servicios avanzados de protección y optimización de datos.
* Asocia las credenciales de tu proveedor de cloud con un agente de la Console para hacer un seguimiento seguro del uso de los servicios de cloud y conectar las implementaciones a la suscripción correcta para una facturación y gestión de costes precisas.




=== Arquitectura de agente

Los agentes funcionan con procesos ligeros que:

* Extrae o envía datos hacia y desde la aplicación Console SaaS (modos estándar y restringido) o funciona de forma puramente local (modo privado)
* Inicia todas las comunicaciones: la NetApp Console nunca inicia llamadas salientes a los agentes
* Conéctate a tus sistemas de almacenamiento usando protocolos de gestión estándar
* Usa TLS 1.3 para una comunicación segura con los proveedores cloud y las API de la NetApp Console




=== Disponibilidad de agentes y requisitos operativos

Los agentes de Console son una infraestructura crítica para NetApp Console. NetApp Console puede soportar interrupciones breves, pero los agentes deben permanecer operativos y accesibles para que la gestión y los servicios de datos no se interrumpan. Tú eres responsable de garantizar:

* Los agentes siguen en funcionamiento
* Los agentes tienen conectividad de red a los puntos finales requeridos
* Los fallos de infraestructura se resuelven rápido
* Las máquinas virtuales de los agentes se mantienen y se actualizan según las recomendaciones de NetApp




== Cuando necesites un agente de Consola

Necesitas desplegar al menos un agente de Console cuando quieras:

* Usa los modos de despliegue restringido o privado (Console instalada en tu propio entorno). Se requieren agentes adicionales para habilitar algunos servicios.
* Accede a servicios avanzados de datos (NetApp Backup and Recovery, NetApp Disaster Recovery, NetApp Ransomware Resilience, NetApp Data Classification y más).
* Administra sistemas Cloud Volumes ONTAP.
* Realiza tareas de gestión avanzadas en clústeres ONTAP locales.
* Haz un seguimiento de las licencias, monitoriza la salud del almacenamiento y planifica las actualizaciones del ciclo de vida.


Sin un agente, puedes realizar una detección básica del almacenamiento y acceder a un conjunto limitado de funciones de supervisión y gestión del almacenamiento. Sin embargo, la mayoría de los casos de uso empresarial requieren uno o más agentes operativos.

link:concept-modes.html["Obtenga más información sobre los modos de implementación de la NetApp Console"] para entender cuándo necesitas un agente y las capacidades que habilitan los agentes.



== Opciones de despliegue para agentes de Console

Puedes desplegar agentes de Console en:

* Amazon Web Services (standard, restricted o private modes)
* Microsoft Azure (standard, restricted o private modes)
* Google Cloud (standard, restricted o private modes)
* En tus instalaciones (modos estándar o privado)


El modo de despliegue de tu consola, el entorno de almacenamiento y tus necesidades de soberanía de datos determinan dónde despliegas los agentes. Despliega varios agentes en distintos entornos para la separación organizativa o por necesidades empresariales.

Después de desplegar un agente, registras ese agente en tu organización de NetApp Console para habilitar capacidades para esa organización. Puedes asociar varios sistemas de almacenamiento y servicios de datos con un solo agente, o desplegar varios agentes en diferentes entornos para la separación organizativa o necesidades del negocio.



=== Agentes para la aplicación SaaS de NetApp Console (modo estándar)

Implementa agentes en tu cloud o en tus instalaciones para conectar con la aplicación SaaS Console alojada en la nube. Los agentes permiten funciones avanzadas mientras la interfaz de usuario de Console sigue siendo accesible desde cualquier lugar.

Puedes instalar agentes directamente desde la Console cuando usas la aplicación SaaS (modo estándar). Puedes instalar en AWS, Azure o Google Cloud, o manualmente en tus instalaciones en tu propio host Linux o en tu entorno VCenter.

Cuando instalas un agente en tus instalaciones, puedes asociar las credenciales del proveedor de cloud correspondiente para habilitar la integración de facturación y los servicios de datos.



=== Agentes para NetApp Console en modo restringido

Necesitas instalar un agente desde el que los usuarios accederán a la NetApp Console. Se necesitan agentes adicionales para habilitar los servicios de datos y gestionar los sistemas de almacenamiento.

Si estás usando NetApp Console en modo restringido, instalas los agentes desde el marketplace de tu proveedor de cloud, o instalando manualmente el software en tu propio host Linux en la cloud, en tus instalaciones o en tu entorno VCenter.

Necesitarás instalar un agente desde el que los usuarios accederán a la NetApp Console. Se necesitan agentes adicionales para habilitar los servicios de datos y gestionar los sistemas de almacenamiento.

Cuando instalas un agente en tus instalaciones, puedes asociar las credenciales del proveedor de cloud correspondiente para habilitar la integración de facturación y los servicios de datos.



=== Agentes para NetApp Console en modo privado (en las instalaciones o en la nube sin conectividad saliente)

Necesitas instalar un agente desde el que los usuarios accederán a la NetApp Console. Se necesitan agentes adicionales para habilitar los servicios de datos y gestionar los sistemas de almacenamiento.

Instala agentes en tu centro de datos o en un entorno aislado por aire. Los agentes no tienen conectividad con los endpoints de la API de NetApp. Todas las operaciones permanecen locales, con total soberanía de datos y control.

Necesitarás instalar un agente desde el que los usuarios accederán a la NetApp Console. Se necesitan agentes adicionales para habilitar los servicios de datos y gestionar los sistemas de almacenamiento.

Cuando instalas un agente en tus instalaciones, puedes asociar las credenciales del proveedor de cloud correspondiente para habilitar la integración de facturación y los servicios de datos.



=== Usa varios agentes cuando lo necesites

Cada agente funciona de forma independiente y puede gestionar varios sistemas de almacenamiento y servicios de datos. Despliega varios agentes cuando lo necesites:

* Aislamiento por tipo de almacenamiento o función organizativa
* Cumple los requisitos de segmentación geográfica o de red
