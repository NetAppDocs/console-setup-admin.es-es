Un agente de Console es un componente de software ligero que instalas en tu red para conectar tu infraestructura de almacenamiento a la NetApp Console. Permite la orquestación avanzada del almacenamiento, los servicios de datos y la integración segura con la cloud.



== Qué hace un agente de Console

Un agente de Console salva la brecha de conectividad entre tus sistemas de almacenamiento y NetApp Console. Conecta de forma segura tu infraestructura a las APIs de NetApp y a Console, permitiéndote:

* Descubre y supervisa los sistemas de almacenamiento en AWS, Azure, Google Cloud y entornos locales desde la NetApp Console.
* Orquesta las tareas de aprovisionamiento de almacenamiento y configuración en los sistemas de almacenamiento desde la NetApp Console.
* Usa flujos de trabajo inteligentes para la protección y gestión de datos.
* Realiza un seguimiento seguro del uso de los servicios en la nube y conecta las implementaciones a la suscripción correcta para una facturación y gestión de costes precisas.




=== Arquitectura del agente de consola

Los agentes funcionan con procesos ligeros que:

* Extrae o envía datos desde y hacia la aplicación NetApp Console SaaS (modo estándar y modo restringido)
* Inicia todas las comunicaciones: la NetApp Console nunca inicia llamadas salientes a los agentes
* Conéctate a tus sistemas de almacenamiento usando protocolos de gestión estándar
* Usa TLS 1.3 para una comunicación segura con los proveedores cloud y las API de la NetApp Console




=== Disponibilidad del agente de la consola y requisitos operativos

Los agentes de consola son fundamentales para NetApp Console. Los agentes deben permanecer operativos y accesibles para que los servicios de gestión y datos sean ininterrumpidos. Tú eres responsable de garantizar:

* Los agentes siguen en funcionamiento
* Los agentes tienen conectividad de red a los puntos finales requeridos
* Los fallos de infraestructura se resuelven rápido
* Las máquinas virtuales de los agentes se mantienen y se actualizan según las recomendaciones de NetApp




== Cuando necesites un agente de Consola

Necesitas desplegar al menos un agente de Console cuando quieras:

* Usa los modos de despliegue restringido o privado (NetApp Console instalada en tu propio entorno). Es posible que se necesiten agentes adicionales para habilitar algunos servicios.
* Accede a servicios avanzados de datos (NetApp Backup and Recovery, NetApp Disaster Recovery, NetApp Ransomware Resilience, NetApp Data Classification y más).
* Administra sistemas Cloud Volumes ONTAP.
* Realiza tareas de gestión avanzadas en clústeres ONTAP locales.
* Haz un seguimiento de las licencias, monitoriza la salud del almacenamiento y planifica las actualizaciones del ciclo de vida.


Sin un agente, puedes realizar una detección básica del almacenamiento y acceder a un conjunto limitado de funciones de supervisión y gestión del almacenamiento. Sin embargo, la mayoría de los casos de uso empresarial requieren uno o más agentes operativos.

== Opciones de despliegue para agentes de Console

Puedes desplegar agentes de Console en:

* Servicios web de Amazon
* Microsoft Azure
* Google Cloud
+
Para gestionar los recursos de Google Cloud, despliega tu agente en Google Cloud. Un agente local no puede gestionar los recursos de Google Cloud.

* En tus instalaciones (solo en los modos estándar o privado)


El modo de despliegue de tu consola, el entorno de almacenamiento y tus necesidades de soberanía de datos determinan dónde despliegas los agentes. Despliega varios agentes en distintos entornos para la separación organizativa o por necesidades empresariales.

Puedes desplegar agentes directamente desde la Console, desde tu cloud marketplace o manualmente en VCenter o en tus instalaciones. link:concept-agent-install-options.html["Compara los métodos de implementación para elegir el más adecuado para tu entorno"].



=== Agentes para la aplicación SaaS de NetApp Console (modo estándar)

Implementa agentes en tu cloud o en tus instalaciones para conectar con la aplicación SaaS Console alojada en la nube. Los agentes permiten funciones avanzadas mientras la interfaz de usuario de Console sigue siendo accesible desde cualquier lugar.

Puedes instalar agentes directamente desde la Console cuando usas la aplicación SaaS (modo estándar). Puedes instalar en AWS, Azure o Google Cloud, o manualmente en tus instalaciones en tu propio host Linux o en tu entorno VCenter.



=== Agentes para NetApp Console en modo restringido

En modo restringido, los usuarios acceden a la NetApp Console directamente desde un agente instalado, no desde la aplicación SaaS alojada en la nube. Debes instalar al menos un agente para que sirva como punto de acceso a la Console. Se necesitan agentes adicionales para habilitar los servicios de datos y gestionar los sistemas de almacenamiento.

Instala agentes desde el marketplace de tu proveedor de nube o instalando manualmente el software en tu propio host Linux en la nube, en tus instalaciones o en tu entorno VCenter.



=== Agentes para NetApp Console en modo privado (en las instalaciones o en la nube sin conectividad saliente)

En modo privado, los usuarios acceden a la NetApp Console directamente desde un agente instalado. Debes instalar al menos un agente para que sirva como punto de acceso a la Console. Se necesitan agentes adicionales para habilitar los servicios de datos y gestionar los sistemas de almacenamiento.

Instala agentes en tu centro de datos o en un entorno aislado por aire. Los agentes no tienen conectividad con los endpoints de la API de NetApp, y todas las operaciones permanecen locales, con total soberanía de datos y control.



=== Usa varios agentes cuando lo necesites

Cada agente funciona de forma independiente y puede gestionar varios sistemas de almacenamiento y servicios de datos. Despliega varios agentes cuando lo necesites:

* Aislamiento por tipo de almacenamiento o función organizativa
* Requisitos de segmentación geográfica o de red


Por ejemplo:

* En un entorno multicloud, puedes desplegar un agente en AWS y otro en Azure. Cada agente gestiona los sistemas Cloud Volumes ONTAP en su entorno respectivo.
* Un proveedor de servicios puede utilizar una organización de Console para prestar servicios a los clientes y otra organización para la recuperación de desastres de una unidad de negocio. Cada organización necesita su propio agente.




== Actualizaciones del agente de consola

Los agentes en la nube se actualizan automáticamente cuando tienen acceso a Internet saliente. Para los agentes sin acceso a Internet (modo privado), consulta link:task-upgrade-agent.html["Administrar actualizaciones del agente de la consola"] para obtener instrucciones de actualización manual.
